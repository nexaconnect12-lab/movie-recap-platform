# Database design
Implemented schemas: jobs, media and video. EF generated InitialJobs, AuditOrdering, ManualMediaImport, MediaDiscoveryInbox, MediaStreamSelection, VideoSceneAnalysis, VideoAudioExtraction and VideoFrameSampling migrations and model snapshot are in src/Infrastructure/Persistence/Migrations. EF migration history is in the default public schema.

ProcessingJobs: UUID primary key; Kind (64), unique IdempotencyKey (128), string Status (32), Attempts, MaxAttempts, Progress, CreatedAt/UpdatedAt/AvailableAt (timestamptz), nullable WorkerId (128), LeaseToken/LeaseExpiresAt, ErrorCode (128), Version UUID concurrency token. Indexes on Status+AvailableAt and LeaseExpiresAt. Checks constrain progress and retry budget.

AuditLogs: UUID key, JobId restrictive foreign key, action (64), resulting status (32), attempt and UTC timestamp; index JobId+At. A database-generated unique Sequence orders events deterministically even when timestamps match. No delete API. Audit retention/export is future administration work.

Claim transaction: SELECT candidate ORDER BY availability/creation LIMIT 1 FOR UPDATE SKIP LOCKED. Save lease/state and audit before committing. Normal state changes lock the row and verify the supplied version; worker mutations verify the execution token and expiry. Unique-key collisions during creation return the original matching job; conflicting parameters yield 409. A single EF SaveChanges transaction saves job creation and audit.

Run migrations explicitly before starting hosts. Neither host migrates on startup, avoiding competing schema changes and excessive runtime privileges. Use a migration role with DDL and a runtime role with schema USAGE and table SELECT/INSERT/UPDATE. Restrict runtime DELETE. Local compose's recap role is a development-only database administrator.

The master prompt's remaining entities are designed in module-catalog.md and deferred to the phases that implement their behaviors. No speculative empty tables are added. Never persist plaintext access/refresh tokens. Backups, retention, migration rollback testing and least-privilege role provisioning are production work.

Phase 2 additive migration `20261012121403_ManualMediaImport` creates the `media` schema:
- MediaAssets: UUID identity, unique SHA-256, positive byte size, creation UTC, container/duration/video codec/dimensions/fps and optional audio metadata.
- MovieImports: UUID, unique request key and JobId, folder alias/relative path, source/requester, retry budget/created UTC, nullable AssetId/CompletedAt and duplicate flag. Completion fields have a consistency constraint; AssetId is a restrictive same-module FK.
- MediaRights: one restrictive same-module import FK; owner, authorization assertion, license evidence, permitted uses/platforms, attribution and optional expiry. Rights do not transfer between duplicate imports. No publishing/token fields exist.

No FK/navigation crosses to Jobs. An Infrastructure Jobs transaction adapter implements Application contracts on the same database transaction for creation/fenced completion/audit. Equal request keys and hashes use transaction advisory locks and unique indexes. Status queries use repeatable read. Readiness now verifies all four implemented table sets (jobs plus three media tables). Existing migrations remain intact; migration Up is additive. Down drops only the three media tables and is destructive to Phase 2 records, so it is not automatically applied to the user's database.

MediaDiscoveryInbox adds media.MediaDiscoveries and nullable MovieImports.ExpectedFingerprint. Discoveries store folder/path, compact SHA-256 path key, metadata fingerprint, byte size, state, availability/error, timestamps, Version, current-revision marker and optional local import/submission references. A filtered unique (Folder,PathKey) index where IsCurrent enforces one current location revision; historical rows remain. Submission-consistency/fingerprint checks and a restrictive same-module ImportId FK protect state. Reconciliation takes per-folder advisory and candidate-row locks; older observations cannot overwrite newer ones. Shared import-row locks make idempotent replay views consistent while completion is in progress. Readiness also queries discovery storage. Up adds a nullable column/table/indexes; Down removes those additions and is destructive to discovery history.

MediaStreamSelection adds five Media tables without rewriting old data:
- StreamInventories: one immutable asset FK, Version and real inspection UTC timestamp; (AssetId,Version) alternate key binds choices to the inventory identity.
- MediaStreams: composite asset/global-index key, restrictive inventory FK, full typed stream metadata/optional fields. Index consistency is constrained.
- StreamSelections: one import FK, inventory-version FK, concurrency Version, nullable chosen indexes/time/operator. Initial state is explicitly unselected; state consistency is constrained.
- StreamSelectionAudits: restrictive import FK, ordered database-generated unique Sequence, before/after/inventory versions, chosen indexes/operator/time. State and audit save in one transaction.
- StreamInspections: import FK, unique job identity and unique import-scoped request key/retry budget; no cross-schema Jobs FK/navigation.

New import/fenced reinspection completes inventory/selection initialization with job success/audit through IJobTransaction. Old assets have no inventory row until real inspection; no track backfill is fabricated. Existing inventory is immutable; contradictory probe data aborts. Selection uses a row lock/version check while source hash verification/read lock remains held. Readiness checks all five tables. Migration Up is additive; Down removes only these tables and is destructive to their records, so it is not applied to the existing application database automatically.


VideoSceneAnalysis adds the module-owned `video` schema, bringing migration count to six. SceneAnalyses stores operation identity, import/asset/inventory/selection/source hash/size/video binding, unique import/request key, unique job identity, actor/settings/attempt budget and completion provenance (runtime versions, PTS timing mode/offset, duration/frame totals and VFR). MovieScenes stores ordered exclusive-end frame/time ranges with a restrictive local analysis FK and analysis/ordinal key. Checks constrain settings, bindings, ranges and completion consistency. There are no cross-module FKs/navigations. Media's Application transaction contract owns shared selection-row locking/validation; Jobs owns fenced state/audit mutations. New operation/job/audit and completed analysis/ranges/job/audit each commit atomically. Readiness queries both new tables. Migration Up creates only new schema/tables/indexes; no prior record rewrite/backfill or invented scenes. Down is destructive to scene history and is never automatically applied. Existing application database is unchanged during verification.

VideoAudioExtraction is the seventh migration, adding only video.AudioExtractions. It stores operation/import/asset/inventory/selection identities, explicit audio index, original SHA-256/size, unique import/request key, unique job ID, actor/retry budget/profile/timestamps and nullable completion token/hash/size/samples/FFmpeg version. Checks enforce source identity, fixed profile and all-or-none completion/PCM length. No cross-schema FK/navigation exists. Request/job/audit and completion/reference/job/audit are atomic through Jobs contracts. A per-operation advisory lock coordinates promotion and cleanup; Media's transaction contract holds a shared choice lock. Filesystem rename is not transactional with PostgreSQL: unreferenced files stay inaccessible and are reconciled, while committed references survive uncertain outcomes. Readiness queries the new table. Up is additive; Down destroys extraction records and is not applied automatically. Restore must pair database and artifact tree; no file bytes/local root paths or secrets are stored in the table.


VideoFrameSampling is the eighth migration, adding only video.FrameSamplings and video.FrameSamples (16 application tables total). FrameSamplings has a restrictive local SceneAnalysisId FK, unique analysis/request key and job ID, operator/sample count/retry budget/profile/timestamps and nullable completed token/FFmpeg version. FrameSamples uses (SamplingId,Ordinal) composite key and restrictive local sampling FK; stores scene ordinal/frame index/normalized range and nullable actual source/normalized seconds/hash/bytes. Checks enforce fixed settings/profile, valid plan and all-or-none completion fields. Plans are inserted with operation/job/audit; they are not successful media. All image metadata and batch reference/job success/audit commit atomically after fenced promotion. No cross-module FK/navigation is added; immutable SceneAnalysis carries full source/selection identity. Cleanup shares the operation advisory lock and preserves the committed token/active attempts. Readiness checks both tables. Up is additive; Down destroys frame records and is not applied automatically. Backups must preserve referenced batch directories with database state.
