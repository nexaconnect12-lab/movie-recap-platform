# Phase 2 scene thumbnails and frame sampling

The separately proposed frame-sampling slice was confirmed on 2026-10-13 (Asia/Singapore). Existing solution/instructions/docs were inspected before authorized edits. Source media, import rights, running original hosts and application database were preserved; verification uses isolated outputs and disposable databases/artifact roots.

VideoProcessing Domain owns fixed-profile request/plan/result invariants. Application owns sampling/history/download/execution and extractor/artifact/store ports. Infrastructure persists FrameSamplings and FrameSamples with local SceneAnalysis/sampling FKs; same-module immutable analysis supplies source/selection provenance. It queries no Media/Jobs tables directly, using Media selected-video/selection transaction contracts and Jobs lease/completion contracts. API and worker compose the real adapters.

Requests require completed current scenes; defaults sample one middle decoded frame per scene, optional 1–3 samples, no duplicates in short scenes and an explicit 300-image cap. Real FFmpeg selects the chosen global stream's decoded ordinals, preserving input PTS and reporting actual integer timestamps/timebase. Persist both original source time and scene-normalized time, validating the latter against the original scene bounds. VFR/nonzero offsets are tested; no frame/FPS guess or approximate seek is used. Outputs are fixed 320×180 RGB PNG fits with black padding, no cropping/auto rotation/semantic selection.

Shell-free bounded subprocess execution kills the owned tree on timeout/cancellation; raw diagnostics are discarded after bounded timing extraction. Each PNG receives full CRC/fixed-header/zlib/pixel/length/hash validation before staging and download. Per-lease batch directories/locks are flushed, revalidated and renamed without overwrite under publication fences. All result metadata/reference/job/audit commits together; rollback/crash orphans remain inaccessible. Reference-aware cleanup preserves committed/active/unknown files. Shared root/ownership/link guards are reused by audio without changing its namespace/profile.

VideoFrameSampling is the eighth additive migration and creates only two tables; planned rows are not fabricated successful images. Lifecycle commands remain existing Jobs endpoints. Successful old batches remain downloadable history after choice changes. Original application schema/hosts are not auto-upgraded/restarted.

See [API/configuration](../api/scene-frames.md), [ADR 0010](../decisions/0010-source-bound-scene-frames.md), and [verification](phase-2-frames-verification.md). Limits: decode/hash costs, fixed samples without semantic scoring, 300 images, shared trusted roots, per-attempt caps without a global quota/retention service or OS memory sandbox, and filesystem/database crash windows. No ASR/AI/TTS, subtitle extraction, recap rendering, UI or publishing is implemented.

Next proposed Phase 2 slice: operator review and validation of the prepared scene/audio/frame artifacts, with bounded listing and artifact availability checks. It requires separately confirmed scope; Phase 3 transcription/AI work must not begin implicitly.
