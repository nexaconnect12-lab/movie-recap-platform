# Phase 2 prepared-artifact review and validation

The separately proposed preparation-review slice was confirmed on 2026-10-13 (Asia/Singapore). Existing instructions/solution/docs were inspected before authorized edits. Original media, import rights, running original hosts and application database are preserved; verification uses isolated binaries, owned temporary storage and disposable PostgreSQL databases.

VideoProcessing Domain adds canonical snapshot bindings, bounded validation reports, versioned Pending/Approved/Rejected/Stale review behavior and ordered audit records. Application adds combined view/current readiness, validation/check/execution and decision ports. Media Application now supplies primitive source/rights/track/choice contracts and source verification/transaction locking; its Media-owned adapter alone queries that schema. Preparation persistence queries Video-owned tables and composes Jobs contracts; no later-phase implementation is created.

Current bundles choose newest completed matching scenes, their completed frames and selected audio if required, with bounded recent operation history. Validation jobs retain the exact chosen binding/hash and actually read/check source/WAV/PNG files under existing validators. Held read handles plus source rehashing protect ordinary local writes/deletes through fenced report commit. Readiness is distinct from integrity; a succeeded check job can honestly report passed=false with issues. No simulated media completion is used.

Approvals require a current matching successful validation and fresh file verification; rejections can record incomplete preparations with required notes. All decision/state/version/audit writes are atomic and optimistic-versioned. Import-level publication locks synchronize new scene/audio/frame completions with final validation/review checks, and Media choice locks revalidate source/selection binding. Changed metadata or new validation makes prior decisions stale while historical bindings/actor/notes remain inspectable. No background monitor is added, so overview is a metadata/last-observation view, not a continuous availability guarantee.

VideoPreparationReview is the ninth additive migration, creating three tables without rewriting previous sources/rights/scenes/audio/frames or creating invented approvals. API/worker registration/readiness/lifecycle now supports the check kind; generic Jobs creation rejects its namespace. Both hosts need the same trusted roots for integrity checks, including the API's fresh approvals. Preparation approval leaves rights Unreviewed and grants no publishing authorization.

See [API/configuration](../api/preparation-review.md), [ADR 0011](../decisions/0011-preparation-validation-review.md) and [verification](phase-2-preparation-verification.md). Limits: full hash cost/long HTTP checks, retained read handles, trusted shared-root deployment, immutable completed metadata, synchronized clocks, no global monitoring/retention or production identity system. No AI/ASR/TTS, recap rendering, UI or publishing is implemented.

Next work is a separately scoped Phase 2 activation/acceptance rehearsal with the configured local roots and protected environment. Other preprocessing and Phase 3 transcription/AI remain separately authorized work; do not infer completion of all Phase 2 capabilities or start a later phase automatically.
