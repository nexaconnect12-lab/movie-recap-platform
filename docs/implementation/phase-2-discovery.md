# Phase 2 folder-monitoring and discovery-inbox slice

Changes were proposed and explicitly confirmed before modifying existing files. Scope: optional worker-hosted notifications + periodic reconciliation, persistent discovery revisions, stable/readable candidates, authenticated inbox APIs, explicit source/rights submission and atomic integration into existing import jobs. No later phase is included.

Media Domain owns MediaDiscovery and transitions; Application owns observation/scan/store contracts and submission orchestration. Infrastructure owns safe local enumeration/fingerprints, scan/candidate persistence, and shared Media import transaction composition. Worker hosts DiscoveryMonitor; API composes inbox endpoints. No Media code queries another module's tables. Jobs creation/audit remains through IJobTransaction. Discovery is disabled by default.

Additive migration `20261012131558_MediaDiscoveryInbox` creates media.MediaDiscoveries, a filtered unique current-location index, state/date index, local ImportId FK and consistency constraints; adds nullable ExpectedFingerprint to MovieImports. Old manual records remain valid. Existing migrations are retained. Reconciliation uses a folder advisory lock and candidate row locks; obsolete scans cannot supersede newer observations. Atomic submission uses candidate + import-key locks and saves the candidate/import/rights/job/audit together. Shared import-row locks make replay views consistent with completion.

Notifications are coalesced hints. Startup/periodic scans remain authoritative, recovering missed events or worker restarts. Incomplete/capped scans do not falsely mark other files missing. Changed file metadata creates a new current revision while retaining submission/dismissal history. Repeated scans of unchanged readable files preserve Version once Ready. Execution checks the approved file fingerprint before probing and checks stability after opening, preventing approval from silently applying to changed sources.

Meaningful coverage includes partial-copy/read locks, missing roots/files, cancellation, scan limits, safe recursion/junction rejection, readiness/version transitions, concurrent scans and submissions, stale/partial reconciliation, idempotent replay, invalid rights, transactional fault rollback, post-submission replacement, migration preserving old manual import/rights, and separate API/worker restart/missed-event smoke with real FFprobe. See [verification](phase-2-discovery-verification.md).

Limits: metadata-based discovery identity, trusted stable root configuration, reference-only source storage, bounded folder scans, coarse import progress, no inbox cursor pagination/retention UI or folder-level dashboard. Rights stay caller assertions and Unreviewed; no automatic import on discovery. Next Phase 2 slice: fuller stream inspection/selection and PySceneDetect scene detection. AI, TTS, rendering and publishing are absent.
