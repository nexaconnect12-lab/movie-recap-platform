# Phase 2 stream inspection and selection

Changes were proposed after inspecting current instructions/implementation and explicitly confirmed before modifying existing files. Scope: full FFprobe stream inventory, per-import explicit/versioned choices and atomic audit, verified original sources, additive storage, and real legacy reinspection jobs. PySceneDetect and later phases remain outside scope.

Media Domain contains framework-free stream metadata, inventory invariants and selection transitions. Application owns inventory/selection/reinspection contracts and source-verification ports. Infrastructure implements detailed FFprobe parsing, read-only verification, stream persistence and shared Jobs transaction composition. Hosts expose authenticated endpoints and worker dispatch for media.stream-inspection. No module reads another module's tables.

New real imports persist immutable asset inventories and initialize unselected choices in the fenced completion transaction. Missing inventories remain explicitly Uninspected, including migrated records; summaries are never expanded into guessed tracks. Duplicates share immutable content inventory but not choices. Real reinspection verifies original SHA-256/size, persists missing data atomically with job success/audit, and leaves previous choices/rights/import identity intact. Contradictory inventory fails instead of replacing known data.

Selection validates category/index/eligibility and current Version, hashes original source content, then revalidates and saves state/audit together while retaining a read-only source handle. A second hash under the selection-row lock detects same-size/timestamp-preserving byte changes. Cancellation or source/audit failures leave selection unchanged. Actors and before/after/inventory versions are captured in ordered audit records.

Additive migration `20261012203152_MediaStreamSelection` creates Media-owned StreamInventories, MediaStreams, StreamSelections, StreamSelectionAudits and StreamInspections. Local restrictive references, immutable inventory-version binding, unique operation/job keys and index/state constraints are included. Existing tables/migrations/data are preserved. See ADR 0007, [API guide](../api/media-streams.md) and [verification](phase-2-streams-verification.md).

Owned fixtures include two video/three audio streams (English/Japanese/unknown labels), forced SubRip subtitle, cover-art MP4 and existing silent video. Tests exercise malformed indexes/metadata, optional values, eligible selections, concurrency/stale versions, source content changes, read locks/cancellation, atomic audit rollback, real legacy reinspection/idempotency/fencing/recovery, additive upgrades, API access and separate-host execution.

Limits: metadata-based eligibility without full decode/extraction, 256 streams, two source hash passes and potentially long HTTP/row-lock time for large media, trusted stable folders/reference-only storage, no automatic inventory reconciliation across conflicting provider output, existing shared-key actor/rights assertions and no publication approval. Next Phase 2 slice: PySceneDetect scene detection using selected video through Media Application contracts. No AI, TTS, rendering, dashboard or publishing is implemented.
