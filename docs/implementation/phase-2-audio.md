# Phase 2 selected-audio extraction

The selected-audio extraction slice was proposed and confirmed on 2026-10-13 (Asia/Singapore). It implements real chosen-track decode and a local artifact lifecycle only. Existing sources/rights/hosts/application database remain preserved; verification uses isolated output binaries and owned disposable storage/databases.

VideoProcessing Domain owns AudioExtraction binding/completion and validates decoded sample/artifact identity/hash/size/profile. Application owns requests/history/download/execution and artifact/extractor/storage ports. Media Application supplies explicit chosen audio/source contracts; its Infrastructure adapter validates the selection under shared row locks. Video persistence queries only its own AudioExtractions table and composes Jobs transaction contracts for atomic creation and fenced completion/audit.

Real FFmpeg runs shell-free with bounded stdout/stderr, single decoder/filter thread settings and cancellation/timeout process-tree termination. It maps the chosen global stream into 16 kHz mono 16-bit PCM. The host builds canonical WAV from actual decoded samples, validates the header/length/hash, and flushes staged output. Full source hashing before/after decode preserves imported content identity under a read-only handle. Resource limits fail explicitly rather than silently truncate. No successful tool output is emulated in tests.

Each attempt is identified by lease token. An owned operation directory contains temporary/promoted files and exclusive attempt locks. Publication takes operation/job/selection locks, revalidates/promotes without overwrite, rechecks lease expiry and commits reference/job/audit. The API serves only durable references and verifies bytes under a read handle. Rollback/uncertain commit outcomes/abrupt termination are reconciled by reference-aware cleanup, which skips active/committed output and preserves unknown files. Cleanup is automatic around execution or explicit for abandoned operations; completed history and tiny ownership/lock files are retained.

Migration VideoAudioExtraction adds one `video` table without prior-data rewrite or cross-module FKs. New authenticated routes create/list/read/download/cleanup; shared Jobs commands remain the lifecycle interface. Previous successful artifacts remain historical after selection changes. Existing application data is not automatically upgraded.

See [API/configuration](../api/audio-extraction.md), [ADR 0009](../decisions/0009-selected-audio-artifacts.md) and [verification](phase-2-audio-verification.md). Limits include trusted separate local roots, shared visibility for both hosts, filesystem/DB crash windows, full hashing costs, coarse progress, fixed downmix/resample profile, no source PTS/video-alignment contract and no global disk quota/retention service. No ASR, AI, TTS, subtitle/frame extraction, preprocessing beyond the fixed audio profile, rendering, UI or publishing is implemented.

Next proposed Phase 2 slice: source-bound scene thumbnails/frame sampling using the artifact lifecycle, with explicit timestamp mapping and owned fixtures. It requires separate confirmation; do not start later phases automatically.
