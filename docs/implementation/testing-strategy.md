# Testing strategy

Local activation adds operational coverage outside the .NET suite: `scripts/Test-ActivatedHostGuards.ps1` rejects duplicate starts and stale/wrong process identities against running hosts; `tests/Operational/test_rehearsal_artifacts.py` exercises the independent NumPy/OpenCV/WAV verifier against wrong tracks/rates/colors, missing padding and truncated PNGs. Run Python tests in the configured real scene environment. `scripts/Rehearse-Phase2.ps1` exercises the activated database/hosts, deliberately crashes only the tracked worker, and preserves source/history. Both pre-upgrade dumps are verified through actual disposable database restores. See [activation results](phase-2-activation.md); incomplete or `-SkipLifecycle` rehearsals are not full activation verification.
Unit tests cover domain transitions, monotonic progress, lease fencing, retry/backoff/budget, cancellation/pause, validator and forbidden dependencies. Architecture assertions run in the unit test project; no extra runner is introduced.

Integration tests use real PostgreSQL through TEST_POSTGRES. Per-test databases are generated, migrated and removed. Cover concurrent idempotent creation, exclusive claims, transaction audit, expiry recovery, API health/OpenAPI/auth/validation and optimistic versions. Never substitute EF InMemory/SQLite for PostgreSQL locking semantics. A missing test connection explicitly skips database tests and must be reported.

Smoke-Test exercises two actual hosts via HTTP with a real worker and database. Build/publish checks verify Windows-compatible output; SCM administrative installation is a separate environment acceptance check. Future phases require owned media fixtures, bounded subprocess cancellation tests, provider contract tests and production failure injection. See verification.md for this execution's exact results.

Phase 2 adds actual FFprobe checks against owned synthetic fixture files and persisted manual import tests, plus an automated separate-process API/worker smoke. Set TEST_FFPROBE to a real executable. Pure PostgreSQL tests still require only TEST_POSTGRES; combined tests require both. The test-only ProbeProcessFixture exercises subprocess timeout, cancellation, output limits and nonzero exit, never successful media completion. Unit adapter checks cover lexical paths, missing/locked/empty/changing files and reparse points. Real database checks exercise equal-key/hash races, atomic rollback, independent rights, stale leases and retry recovery. All temporary media/db resources are uniquely named and cleaned by their owning test.

Discovery coverage adds state/version stability, busy/empty partial copies, cancellation, scan caps, safe recursion/link exclusion, concurrent scans/submissions, older/partial scan reconciliation, dismissal/revision history, replay, explicit metadata validation, transactional trigger fault rollback, changed-source rejection and migration preserving manual records. Separate-host discovery smoke keeps a partial-copy writer open, checks that no jobs are created automatically, submits rights, executes real FFprobe, restarts the worker after creating a missed-event file, and verifies persistence/source bytes. Tests do not claim deterministic operating-system buffer overflow injection; recovery is tested through incomplete scans and files created without a live watcher.

Stream tests add multi-video/multi-audio/language/forced-subtitle/cover-art/silent fixtures, malformed/duplicate stream indexes, unknown optional metadata, eligible explicit choices, per-import duplicate independence, concurrency/stale versions, same-size/timestamp-preserving source changes, read locks/cancellation, selection-audit trigger rollback, real legacy inspection idempotency/fencing/recovery, additive upgrades, API authorization/required fields and separate API/worker inspection-selection-audit-reinspection smoke. TEST_FFPROBE/TEST_POSTGRES prerequisites remain mandatory for real checks; skipped tests never count as verification.


Scene coverage requires TEST_SCENE_PYTHON with pinned real dependencies as well as TEST_FFPROBE/TEST_POSTGRES for combined tests. Real fixtures cover three known cuts, explicit nonprimary stream, single scene, VFR timestamps and nonzero PTS offset. Database tests exercise concurrent replay, selection changes before/during execution, historical results, source corruption with preserved timestamp, pause/cancel/expired/recovered leases, trigger-injected completion rollback and additive upgrade preservation. Fault subprocess fixtures emit only errors/malformed output/hangs/floods; they never simulate successful media processing. Separate API/worker smoke executes actual Python and verifies persisted ranges/provenance/source preservation. Latest evidence: phase-2-scenes-verification.md.

Audio tests additionally require TEST_FFMPEG. Real existing multi-audio fixtures prove selected nondefault stereo-to-mono decoding through a frequency check (880 Hz versus unchosen 440 Hz), with independent real FFprobe validation of WAV/codec/channel/rate/sample count. PostgreSQL tests cover concurrent replay/conflicts, changed choice/source, historical downloads, trigger-injected fault after promotion, expired/recovered leases and expiry during promotion, orphan cleanup/active locks, explicit no-audio conflicts, authenticated routes and additive prior-data preservation. Unit fault processes never emit successful audio; they exercise output limits/timeouts/cancellation/corrupt-source exit. Artifact tests protect unknown/unowned files and reject links/overlapping roots/truncation/checksum changes. Separate-host API/worker smoke extracts/downloads real audio, verifies audit/hash/history/source preservation and cleanup. Latest evidence: phase-2-audio-verification.md.

Frame tests require actual TEST_FFMPEG/TEST_FFPROBE/TEST_SCENE_PYTHON/TEST_POSTGRES. Real fixtures prove chosen nonprimary red/white/black pixels, VFR actual seconds (not frame/FPS) and nonzero original PTS offsets. Assertions cover 1–3 quantile plans/short scenes/batch cap, full PNG CRC/pixel/truncation checks, concurrent keys, current/unfinished scenes, selection/source changes, historical downloads, post-rename audit fault rollback, crash orphan reconciliation/active locks, pause/cancel/expiry during promotion/recovery, output caps, additive prior-schema preservation and authenticated routes. Fault subprocesses emit only invalid/oversized/hanging/corrupt output, never successful thumbnails. Separate hosts execute actual import/select/scene/sampling/PNG downloads and verify colors/hash/timestamps/audit/history/source preservation. Latest evidence: phase-2-frames-verification.md.

Preparation tests require the existing full real PostgreSQL/FFprobe/FFmpeg/PySceneDetect environment. Actual prepared fixtures exercise combined views, source/WAV/PNG hash/integrity validation, no-audio and incomplete readiness, current-only approvals, required rejection notes, concurrent keys/decisions/version conflicts, exact historical binding persistence, missing/corrupt files, unchanged-timestamp source changes, new prepared batches/selection changes, changes during validation/approval, held read locks, pause/cancel/expiry/recovery, trigger-injected report/decision rollback and additive prior-data/artifact preservation. Separate API/worker frame smoke now validates and approves actual preparation, records audit and observes Stale after a choice change. No provider/tool success is mocked. Latest evidence: phase-2-preparation-verification.md.


Subtitle checks require the existing real PostgreSQL/FFprobe/FFmpeg prerequisites; preparation/host checks additionally use actual pinned scene Python. New tests exercise UTF-8/BOM/CRLF canonicalization, ordered overlaps, malformed times/controls/empty output, physical timeout/cancellation/output caps, source offset and nondefault stream mapping, unsupported real mov_text selection, idempotency/concurrent replay, changed source/choice, trigger rollback after promotion, active/crashed orphans, expired/cancelled/paused leases and expiry during promotion. Real SRT corruption/missing bytes and held read handles join preparation checks; new-artifact/racing approvals must stale/conflict. Migration checks preserve historical rejection bindings and version-1 hashes. Separate API/worker smoke actually extracts SRT, scenes and PNGs, validates/approves and detects staleness while preserving originals/history. No successful subtitle processing is mocked. Latest results: phase-2-subtitles-verification.md.
