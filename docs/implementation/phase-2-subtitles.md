# Phase 2 selected subtitle extraction

The user confirmed the proposed slice on 2026-10-14 (Asia/Singapore). Existing instructions, module/artifact/preparation implementations and documentation were inspected before changes. The activated application database, published release/profile/hosts and original media remain preserved; verification runs with isolated outputs and disposable resources.

Domain adds source-bound SubtitleExtraction, immutable timed cue data and restrictive SubtitleCue records, fixed-profile result/artifact invariants and internal subtitle job support. Application adds request/status/history/download/execution/storage/extractor ports and reserves the job namespace. Media supplies selected-subtitle access and transaction contracts; only its adapters read/lock Media tables. Infrastructure implements actual bounded FFmpeg global-stream extraction, strict UTF-8 SubRip parsing/canonicalization, hash/cue/byte verification, managed lease-attempt artifacts and atomic PostgreSQL publication. API/worker compose the new use case and expose authenticated endpoints, lifecycle and cleanup.

Preparation includes current matching subtitles and ordered cues; selected subtitles require extraction while no-subtitle choices remain valid. Reports and fresh approval hold/reverify the actual SRT alongside source/audio/frames. Publication shares the import preparation lock; new output or changed selection makes prior approval stale. Schema-versioned bindings preserve historical fingerprint calculations and no-subtitle compatibility.

`VideoSubtitleExtraction` is the tenth additive migration: SubtitleExtractions/SubtitleCues plus nullable subtitle IDs and legacy-default binding-version columns on preparation validations/audits. Latest source model has 21 application tables; activated `recap` stays at its nine migrations/19 tables until separate activation. No fictitious extraction/report/approval is generated during migration. No cross-module FK/navigation or Domain framework dependency is added.

See [API/configuration](../api/subtitle-extraction.md), [ADR 0013](../decisions/0013-selected-subtitle-extraction.md) and [verification](phase-2-subtitles-verification.md). `scripts/Set-SubtitleVerificationEnvironment.ps1` composes the existing protected real-tool setup, starts no hosts and applies no live migrations. Unsupported codecs and empty/malformed output fail explicitly. Source timestamps/text are technical extraction data, not translation or speech support. No OCR, ASR/AI, Burmese voice, generated narration subtitles, recap rendering, UI or publishing is implemented.

Next work is separately scoped activation of this subtitle slice, with backups and an owned-fixture rehearsal. Other preprocessing/codec support and later phases remain separate decisions.
