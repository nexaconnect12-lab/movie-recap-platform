# ADR 0008 — Source-bound scenes from selected-video presentation timestamps

Status: accepted, 2026-10-13 (Asia/Singapore).

Use a VideoProcessing module and `video` schema for scene operations/ranges. Keep probes/inventories/choices owned by Media. Consume its Application selected-video/source/transaction contracts and Jobs transaction contract; module implementations access only their own tables. Bind an analysis to import, asset/hash/size, inventory/selection versions and explicit global video index, detector settings, actor and job. Import-scoped idempotency preserves the original binding, including historical replay. No automatic analysis starts when choices change.

Run pinned real PySceneDetect 0.7.1 ContentDetector `content/suppress` through a shell-free Python process; decode with PyAV 19.0.0 directly from the chosen stream rather than relying on a first-video backend or temporary remux. [PySceneDetect's detector API](https://www.scenedetect.com/docs/latest/api/detectors.html) supports processing decoded frames. [PyAV frames](https://pyav.basswood.io/docs/stable/api/frame.html) expose PTS/timebase/duration. Store actual normalized presentation times, original offset, decoded frame ordinals and observed VFR; never derive result seconds from average FPS. Missing/nonmonotonic timestamps or unavailable final end fail. Whole-stream contiguous coverage and runtime/settings provenance are domain invariants. Minimum scene length is in decoded frames, not wall time.

Hold a read-only source handle across hash verification, decode, final hash and fenced completion. Windows sharing denies ordinary writers/deleters. Media's selection row shared lock protects the final binding check while Jobs lease token/expiry fences publication. Analysis/ranges/job success/audit share one PostgreSQL transaction, so pause/cancel/stale execution, changed selection or injected database failure cannot publish partial ranges. Older successful results are immutable and marked noncurrent when choices change. Retries repeat computation against the original binding; there is no external output artifact to duplicate.

Bound subprocess runtime/output and decoded frames/pixels/time/ranges; kill its process tree on cancellation. Discard bounded stderr to avoid storing arbitrary media paths/metadata. Record real tool versions and stable error codes, with coarse progress below completion. Python dependencies are deployed/configured explicitly, never installed by host startup. Own synthetic multi-stream/cut/VFR/offset fixtures exercise actual decoding and PostgreSQL behavior.

Tradeoffs: full decode plus two hashes can be expensive; timestamps require bounded linear storage; pixel checks follow decoder allocation, so this is not an OS memory sandbox; decoder support differs from metadata eligibility; missing valid timestamps/end time is rejected; simple content boundaries may miss fades or split motion; shared-key actor/rights assertions are unreviewed. No semantic labeling, thumbnails, extraction, preprocessing, AI/TTS/rendering or publishing is implied.
