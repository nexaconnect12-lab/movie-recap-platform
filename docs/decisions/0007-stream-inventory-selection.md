# ADR 0007 — Immutable stream inventory with per-import source-verified selection

Status: accepted, 2026-10-13 (Asia/Singapore).

Extend the existing Media-owned FFprobe adapter and schema for this Phase 2 slice. Full stream inventory belongs to content identity (MediaAsset); choices belong to MovieImport because different sources/rights assertions/operators must not inherit another import's preferences. New imports atomically commit inventory, an unselected per-import selection row, asset/import result and job/audit success. Selection is explicit; no language or default-disposition heuristic creates an operator choice. The existing metadata summary remains the first non-cover video/first audio summary and is not rewritten when another stream is selected.

Keep every reported stream's global index, category plus raw reported type, codec, language, optional duration, default/forced/attached-picture flags and relevant video/audio properties. Missing/N/A durations remain null, never synthesized from container duration; missing/undetermined language stays null. Preserve attachment/data/unknown types as Other with their reported type, but do not allow selecting them. Cover art cannot be main video. Video eligibility requires codec/dimensions/frame rate; audio requires codec/channels/sample rate; subtitle requires a codec. Selection does not imply decoding/extraction/rendering support.

Inventory is immutable and versioned by identity. Its 256-stream cap complements existing bounded FFprobe output/timeouts. Content duplicates share inventory but receive separate unselected choices. A later probe must agree with the existing inventory or fail with stream-inventory-conflict; automatic rewriting/migrating choices across contradictory provider/version output is deferred. Original summary metadata/rights are preserved.

Add StreamInventories, MediaStreams, StreamSelections, StreamSelectionAudits and StreamInspections in the Media schema with restrictive local references, inventory-version binding, index/state constraints and unique inspection keys/job identities. Domain stays framework-free; Application owns use cases/ports. Infrastructure composes job creation/fenced completion through the existing Jobs IJobTransaction contract, never another module's tables. The new internal media.stream-inspection kind cannot be created through generic Jobs endpoints; stream-inspection: keys are reserved.

Older records are Uninspected until a real probe/hash operation succeeds. An explicit reinspection request atomically creates a Media operation record and its job/audit, with request-key replay scoped to import identity. Worker reuses stability checks, source-preserving read locks, double hashing, bounded FFprobe and lease cancellation/fencing. Source SHA-256/size must match the original asset before writing inventory. Completion initializes that import's selection if needed, without changing existing choices, import job identity, rights or asset. Pause/cancel/expired/stale leases roll back all inventory/selection writes.

Selection is optimistic-versioned and audited atomically, with actor, before/after version, inventory identity, indexes and UTC time. The Application validates a detached candidate before expensive I/O; Infrastructure revalidates under a row lock. A verifier opens the original path read-only and verifies stable SHA-256/size against the asset; discovery imports also honor their bound metadata fingerprint. It retains the read handle across a second hash and selection/audit save. Windows share locks deny writers/deleters during this operation. Cancellation and verification/audit failures roll back the command. This is local consistency, not a distributed transaction with a filesystem under hostile privileged mutation.

Limits: two full hash passes for selection (the final pass holds a database selection-row lock), synchronous HTTP selection duration on large media, trusted stable roots and reference-only sources, immutable inventories without automatic provider-version reconciliation, no full decoding guarantee, and caller-asserted actor/rights under existing shared-key access. All rights remain Unreviewed. Subtitle selection includes text/bitmap codec identities without extracting/using those tracks. PySceneDetect, stream extraction/preprocessing, AI/TTS/rendering/publishing are not included. Future processing must consume Media Application contracts for the chosen streams and reverify sources.
