# ADR 0006 — Folder discovery creates an inbox, not automatic import jobs

Status: accepted, 2026-10-12.

Keep monitoring optional and worker-hosted. FileSystemWatcher events are hints placed in a coalesced bounded channel; callbacks perform no file/database work. Startup and periodic full reconciliation provide correctness after missed notifications, overflow, worker downtime and database failures. Discovery is disabled by default. Missing roots are retried; no persisted timer or scheduling module is introduced.

The Media module owns `MediaDiscoveries`. A metadata fingerprint binds canonical absolute location, byte size, last-write ticks and creation ticks. It is not a SHA-256 content digest; full byte hashing remains the import pipeline's responsibility. Readability and unchanged observations across the configured stability interval allow Ready. Empty/busy files stay Observing. A complete scan marks unseen paths Unavailable. Capped/inaccessible/partial scans do not infer deletions. Roots/ancestors/subdirectories and files reject reparse points; supported extensions are discovered recursively without opening unsupported media. Actual container validation remains FFprobe's job at import execution.

A SHA-256 key of the normalized relative path provides a compact indexed location identity (Windows case-insensitive normalization). A filtered unique index permits one current candidate per folder/path key. Changed fingerprints supersede old candidates with a new identity and version, preserving Submitted/Dismissed history. Folder advisory locks and row locks serialize scan reconciliation. LastObservedAt rejects older scan results. Reconciliation updates observation timestamps without changing Version unless readiness, availability or other material state changes. Submitted records retain their linked import even when their source disappears or a new revision is discovered.

Operators explicitly submit source/requester/rights with a Ready candidate's Version. The API re-observes the file; the database locks the candidate and checks the matching fingerprint/version. Candidate submission, immutable import/rights creation, job creation and its audit commit together using existing Media persistence and Jobs Application contracts. A reserved `discovery:` import key produces one import/job per candidate. Equal submission replays use the original SubmittedVersion and identical metadata; they do not require the source file to still exist. Changes to metadata/version conflict. Dismissal is versioned and suppresses the same revision, not future changed media.

Imports originating in discovery persist ExpectedFingerprint and check it after opening the source, before probing, then enforce ordinary stability/hashes across inspection. This prevents silently processing a replaced/modified source after submission. A changed source fails the old job rather than receiving the old rights record; its new candidate requires another submission. Rights are caller assertions and remain Unreviewed. Manual imports remain usable when monitoring is disabled and keep nullable ExpectedFingerprint for backwards compatibility.

Replay queries take a shared import-row lock while reading its job contract, preventing success/read-result mismatches without acquiring a stale repeatable-read snapshot before advisory-lock waits. Media never reads Jobs tables. All effects remain read-only filesystem operations and fenced/idempotent local database writes; original files are never copied, renamed or deleted by discovery.

Limits: trusted stable folders, metadata-based revision identity, reference-only storage, polling latency, bounded scans and no cursor pagination/retention UI. A privileged actor changing bytes while preserving every observed metadata field is outside this fingerprint guarantee; import still hashes actual bytes and verifies stability. Entries beyond MaxEntriesPerFolder require raising the cap or narrowing folders. Watcher overflow recovery is by periodic rescan; no loss-free event-stream claim is made. Stream selection, PySceneDetect, AI/TTS/rendering/publishing remain future slices.
