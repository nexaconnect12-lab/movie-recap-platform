# ADR 0010 — Scene frame quantiles with actual source PTS and fenced batch publication

Status: accepted, 2026-10-13 (Asia/Singapore).

Extend VideoProcessing with FrameSampling/FrameSample and two `video` tables. A sampling request references a completed immutable SceneAnalysis in the same module; that aggregate supplies source/choice identity and original first-PTS offset. Planned rows retain scene bounds and decoded frame indices. Media Application supplies source handles/snapshots and its own selection-row transaction adapter. Jobs provides locked lease validation and fenced completion/audit. No cross-module table query/FK/navigation or later-phase module is added.

Use deterministic decoded-frame quantiles (1–3 per scene, at most available frames, at most 300 total). One sample uses the middle decoded frame. Sequential selected-stream decoding avoids approximate seeks, default stream guessing and VFR frame/FPS timing estimates. [FFmpeg copyts](https://ffmpeg.org/ffmpeg.html) preserves input offsets; its [select/showinfo filters](https://ffmpeg.org/ffmpeg-filters.html) expose selected frame ordinals and PTS/timebase. Parse integer PTS and rational timebase from a named filter instead of rounded printed seconds. Store actual source seconds and normalized seconds, validating normalized time against the original end-exclusive scene interval. Decoder disagreement/missing timing fails explicitly.

The only image profile is RGB24/noninterlaced 320×180 PNG fitted without cropping, square pixels/black padding, no auto rotation. This is deterministic frame sampling, not semantic highlight scoring or orientation/SAR correction. FFmpeg emits concatenated image2pipe PNGs under size/count/batch/time/diagnostic caps; the adapter stages individual images and checks exact expected count. Full fixed-profile PNG validation covers CRCs and bounded pixel decode, then hashes the file. Source hashes before/after decode retain imported identity under a read-only handle.

Reuse the audio artifact lifecycle's fencing/reconciliation pattern and shared trusted-root/ownership/link guard. Every job lease gets a unique exclusive lock and temporary batch directory. Revalidate staged files and rename the directory without overwrite under operation/job/selection locks; recheck lease expiry before committing batch reference, every image result, job success and audit. Only completed durable references can be downloaded. Rollback/crash after rename leaves an inaccessible orphan rather than partial success. Cleanup uses the same operation advisory lock and durable reference, skips active locks and preserves unknown entries. It deletes known PNGs only and removes empty attempt directories nonrecursively; retained ownership/lock markers avoid lock unlink/reopen races.

Requests are idempotent per analysis/key including actor/sample count/retry budget. Original matching requests replay after choice changes; new requests against historical/unfinished analyses conflict. Retry stays bound to the original analysis. Old successful batches remain immutable downloadable history and are annotated noncurrent; no publication authorization follows from sampling.

Tradeoffs: sequential decode and full hashing cost, fixed technical samples may miss representative action, 300-image batch limit, output caps without aggregate quota/OS memory sandbox, final validation holds publication locks, local shared-root deployment and filesystem/database durability windows. Explicit cleanup/retry reconciles abandoned attempts; global retention remains future. Tests use real FFmpeg/FFprobe/PySceneDetect/PostgreSQL with owned multi-video/cut/VFR/offset fixtures, color/timestamp assertions, post-promotion fault rollback, expiry/recovery/cancellation and separate API/worker smoke. No AI/ASR/TTS, subtitles, recap rendering, dashboard or publishing is delivered.
