# ADR 0009 — Lease-scoped audio artifacts with database-gated publication

Status: accepted, 2026-10-13 (Asia/Singapore).

Extend VideoProcessing Domain/Application and its `video` schema with AudioExtraction. Media remains owner of inventory/choices/source verification; consume its new selected-audio snapshot/source/transaction contracts. Media-owned Infrastructure alone reads/locks Media tables. Jobs owns lifecycle/fencing/audit through Application transactions. No cross-module tables/FKs/navigation or new later-phase module is introduced.

Use a single explicit versioned PCM WAV profile (16 kHz/mono/16-bit) to keep validation/duration/resource bounds deterministic. Real FFmpeg decodes the chosen global audio index to bounded raw PCM stdout; the host writes the RIFF header from actual samples. [FFmpeg documents manual mapping and audio options](https://ffmpeg.org/ffmpeg.html), and [its format documentation describes raw PCM](https://ffmpeg.org/ffmpeg-formats.html). No shell, arbitrary caller filter/output path or default audio selection is exposed. Record actual executable version, profile, sample count/byte size/hash and source/selection bindings. Output sample time is normalized and is not a video synchronization/PTS preservation guarantee.

External filesystem writes must be safe before enabling retries. Every attempt uses operation ID + lease token names beneath a dedicated trusted root. Create temporary files exclusively, retain an exclusive attempt lock and validate exact WAV length/header/hash. Flush before non-overwriting same-directory rename. PostgreSQL cannot atomically commit a filesystem rename: take an operation advisory lock, lock/check the Jobs lease and Media selection, revalidate/promote the attempt, recheck lease expiry, then commit artifact reference/job success/audit together. Only committed references can be downloaded; stale workers cannot overwrite another attempt's file. A failure/crash after rename produces an invisible orphan, not a successful operation.

Cleanup uses that same operation advisory lock and reads the durable reference, so uncertain commit outcomes preserve referenced output. Exclusive filesystem attempt locks skip still-running work. Remove only recognized temporary/promoted files in the owned operation directory, never successful history, unknown names or source media. Retain ownership/lock markers to avoid unlink/reopen races. Cleanup occurs before/after execution and through a scoped authenticated API; stranded failed/cancelled work without another execution needs explicit cleanup. A global janitor/retention policy is deferred. The root must be separate from source roots and contain no links; identities/paths are generated server-side.

Source hashing precedes/follows decode under a retained read-only source handle. Jobs contract adds a lease check that can hold its row lock before filesystem promotion, followed by the existing complete-time expiry check. Database failure rolls back operation/reference/job/audit; cleanup reconciles the orphan. Selection changes reject new completion and leave prior successful artifacts as immutable history. Request-key replay retains original actor/retry budget/selection, and does not silently rebind on retry.

Tradeoffs: full source/output/download hash passes, long publication locks during final artifact verification, coarse progress, local shared-root deployment assumption, per-attempt size caps without aggregate quotas, no OS memory sandbox or distributed transaction, and filesystem metadata durability dependent on deployment storage. Source rights/operator remain caller assertions under shared-key auth. No waveform normalization, transcript/ASR, AI/TTS, subtitle/frame extraction, rendering or publishing is included. Tests use owned existing multi-audio sine fixtures, real FFmpeg/FFprobe and disposable PostgreSQL, including spectrum checks proving chosen-track decode and faults after promotion.
