# ADR 0011 — Snapshot-bound preparation validation and audited operator decisions

Status: accepted, 2026-10-13 (Asia/Singapore).

Keep this Phase 2 technical review in VideoProcessing, adding PreparationReviews, PreparationValidations and PreparationAudits to `video`. Domain owns fingerprints/report/review invariants; Application owns view/check/review/execution ports. Media exposes primitive preparation source/rights/track/selection DTOs and source/transaction contracts. Its Media-owned adapter alone reads/locks Media tables; Video persistence reads only its own module and uses Jobs Application transactions. No speculative later-phase module or cross-schema FK/navigation is created.

Assemble a current bundle from matching explicit choices, newest completed scenes, their newest completed thumbnails and newest matching audio when selected. Keep bounded operation history separately; no queued/failed attempt overrides completed content. Canonical SHA-256 binds import/asset/hash/size/inventory/selection/indexes and immutable completed operation IDs. Persist exact bindings in validation/audit records as well as hashes so history is inspectable after choices change. Missing choices/required content are explicit readiness issues. A source/choice revision check brackets overview assembly to reject mixed revisions.

Use a durable internal preparation-validation job for expensive full source/WAV/PNG integrity work. Sources and artifacts are opened read-only with existing validators; hold valid file handles through report commit and rehash source after artifact checks. Stable bounded issue codes are persisted, never provider output/paths. A finished integrity check can report Passed=false while its execution job succeeds; job success is not an approval or simulated media completion. Lease loss/cancellation/stale bundle or database faults prevent all report/review/audit success writes.

Review creation and validation request/job/audit are atomic. Report, latest-validation pointer/review version/stale state, preparation audit and job completion are atomic. Scene/audio/frame successful publication and preparation mutations share an import-scoped PostgreSQL advisory lock; Media's shared selection lock prevents choice changes during final verification. Recalculate the current bundle under those locks before accepting a report/decision. Concurrent review commands require the current UUID version and snapshot hash. Trigger-injected failure must preserve the prior state/version/audit.

Approve only after successful latest matching validation, and freshly recheck every file again while holding read handles through decision commit. Rejection may record problems in incomplete preparation but requires notes. A new completed validation marks previous decisions stale; changed source/choice/artifact binding yields a derived EffectiveStatus=Stale without rewriting historical decisions. Preserve actor/notes/before-after version/binding/fingerprint/validation/time in ordered audits. Approval is scoped to preparation quality and never changes source permissions or publication rights.

Tradeoffs: full hashes and synchronous fresh approval may be slow, up to 302 retained read handles, no continuous filesystem monitor/automatic revalidation, per-kind bounded history, immutable completed metadata and synchronized clock assumptions, and local trusted filesystem sharing rather than hostile-mutation/distributed storage protection. Raw decision history can differ from effective current status; API consumers must use EffectiveStatus and NeedsValidation. Source and artifact roots must be shared consistently by hosts. New-provider access, AI/transcription/TTS/rendering/UI/publishing and rights approval/revocation are deferred.
